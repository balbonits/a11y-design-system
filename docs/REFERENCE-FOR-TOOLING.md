# Ember UI accessibility reference (for tooling and reviewers)

A single, checkable statement of what Ember UI promises for accessibility, how each promise is tested, and what an app
built on it still has to do. It is written so that a linter, a review checklist or an automated gate can be derived from
it line by line. The target is WCAG 2.2 level AA.

- Snapshot: measured on `main` at 53b37a6 (package 0.3.1), themes `neo` and `kinetic`, light and dark.
- Sources of truth that this file summarizes and must not contradict: `src/themes/*.css` and `src/tokens.json`
  (tokens), `docs/CONTRAST.md` (generated by `npm run contrast`), `scripts/*.mjs` (gates), `src/*.test.tsx` (unit
  tests), and each component's docs page in Storybook. If they disagree with this file, they win and this file is stale.
- Open pull requests that change a promise below are named where they apply ("PR #N"). Until a PR lands, `main`
  behaves as described under "On main today".

## 1. Token contract

### 1.1 Thresholds

| Rule | Threshold | WCAG |
|---|---|---|
| Normal text (under 24 px, or under 18.5 px bold) on its background | 4.5:1 | 1.4.3 |
| Large text | 3:1 (Ember gates all text at 4.5:1) | 1.4.3 |
| UI parts needed to see a control or its state (borders, focus ring, switch track, selected-tab bar, checkbox) | 3:1 against what is next to it | 1.4.11 |
| Focus indicator | visible change on every focusable element; Ember: solid ring, at least 2 px (3 px in both themes), 3:1 against every surface it can sit on | 2.4.7 (and 2.4.13 as a goal) |
| Pointer target | 24 x 24 CSS px minimum; Ember: `--target-min` = 44 px for every shipped control | 2.5.8 (2.5.5 met) |
| Disabled controls | exempt from contrast; disabled fields still use `--text-muted` on `--surface-muted` (4.5:1); disabled buttons and tabs are dimmed to 55 % opacity and are not gated | 1.4.3 note |
| Ratios | computed with the WCAG relative-luminance formula, never rounded up (4.499 fails 4.5) | |

Translucent colours (the modal scrim) are alpha-composited over the colour beneath before a ratio is computed.

### 1.3 Component-level colour use

Each component colour token is `var()` of one contract token (enforced by `npm run tokens` and `npm run lint:colors`),
so the pairs above cover the components:

|---|---|---|---|
| Field text, border | `--field-fg` = `--text`, `--field-border-color` = `--border` | `--field-bg` = `--surface` | text/surface 4.5, border/surface 3 |
| Field error border and message | `--danger` | `--surface`, `--color-bg` | danger/surface 4.5 |
| Hint text | `--text-muted` | `--color-bg`, `--surface` | 4.5 |

| Switch on thumb on track | `--switch-thumb-on` = `--accent-contrast` | `--switch-track-on` = `--accent` | accent-contrast/accent 4.5 |

### 1.4 Focus ring

| Token | neo | kinetic | Rule |
|---|---|---|---|
| `--focus-ring-width` | 3px | 3px | 2 px or more |
| `--focus-ring-style` | solid | solid | solid |
| `--focus-ring-offset` | 3px | 3px | 0 or more; 2 px or more in a theme that defines `--hover-fill` |
| `--focus-ring-color` | `#e0217a` (light and dark) | `#1434B8` light, `#C2CFFF` dark | 3:1 against `--color-bg`, `--surface`, `--surface-muted` (table above); against `--border` too when the offset is 0 |

- One shared rule in `src/ember.css` draws the ring with `:focus-visible` on every interactive part. Inside the tab list
  (which scrolls, and so clips) the ring is inset by its own width.
- A state style (error, selected, checked) must never replace the ring: write the state's `:focus-visible` variant
  after it with higher specificity (see PR #68 for the Checkbox error state).
- Forced colours: the ring is an outline, so it survives; the focus gate checks it there too.

### 1.5 Target size

- `--target-min` is 44 px in both themes. Every Button size, Checkbox row, Switch row, Tab, Table sort button and
  ThemeSwitcher option reaches it. Controls drawn smaller (small Button 36 px, sort button 32 px, 20 px checkbox, 44 x 24
  switch track) get the full hit area from an absolutely positioned `::before` or from a label that covers the row.
- Inline links in running text are exempt (2.5.8 inline exception); Ember renders none.
- `npm run test:target-size` measures the effective hit area by browser hit-testing (calibrated to 0.5 px).

### 1.6 Type and spacing scale (shared primitives)

| Token | Value | Token | Value |
|---|---|---|---|
| `--text-2xs` | 11px | `--space-1` | 4px |
| `--text-xs` | 12px (hints, errors, small buttons) | `--space-2` | 8px |
| `--text-sm` | 14px (labels, buttons, tabs, table) | `--space-3` | 12px |
| `--text-base` | 16px (body, field values) | `--space-4` | 16px |
| `--text-lg` | 18px | `--space-5` | 20px |
| `--text-xl` | 20px (modal title) | `--space-6` | 24px |
| `--text-2xl` .. `--text-7xl` | 24, 30, 36, 48, 64, 80px | `--space-8` .. `--space-16` | 32, 40, 48, 64px |
| `--leading-normal` | 1.5 | `--leading-tight` | 1.1 (display only) |

- Field values are 16 px so mobile browsers don't zoom on focus. Controls use `min-height`, never a fixed height, so
  text spacing overrides (1.4.12) and 200 % zoom don't clip text.
- Control heights: `--control-height` 44 px (neo), 48 px (kinetic).

### 1.7 Motion

| Token | neo | kinetic | Under `prefers-reduced-motion: reduce` |
|---|---|---|---|
| `--duration-fast` | 120ms | 140ms | 0ms |
| `--duration-base` | 220ms | 260ms | 0ms |
| `--duration-slow` | 420ms | 480ms | 0ms |
| `--duration-reveal` | 520ms | 700ms | 0ms |
| `--stagger` | 0ms | 90ms | 0ms |
| `--press-offset` | 3px | 1px | 0px |
| `--lift` / `--tilt` | -3px / -1.5deg | 0px / 0deg | 0 |
| `--parallax-scale`, `--hue-shift`, `--weight-shift` | | | 0 |

- Reduced motion is handled once, in the tokens, plus `animation: none` for the modal and toast entrance and a still
  spinner. Nothing in Ember flashes; nothing moves for more than 5 s (the spinner shows only while an action is busy).
- `npm run test:a11y` checks that the modal, toast and loading stories run no animation under reduced motion;
  `npm run test:press` checks the press offset is 0.

## 2. Components

Shared rules for every component:
- Native element first: `button`, `input`, `select`, `dialog`, `table`, `fieldset`/`legend`. ARIA only where HTML has no
  equivalent (`role="switch"`, tabs, live regions, `aria-sort`).
- Every control has a visible label that is also its accessible name (2.5.3), except icon-only buttons, whose
  `aria-label` the TypeScript type makes required.
- Every state has a story, and every story is swept by axe, target size and the focus gate in both themes and modes.

### 2.1 Button

| | |
|---|---|
| Role / name | native `button`, `type="button"` by default; name from the text, or the required `aria-label` when `iconOnly` |
| States | default, hover, focus-visible, active (moves by `--press-offset`), disabled (native `disabled`), loading |
| Loading | `aria-busy="true"`, a spinner with `aria-hidden="true"`, clicks are ignored, the button stays focusable and keeps its name |

| Key | Action |
|---|---|
| Tab / Shift+Tab | moves focus to / from the button |
| Enter, Space | activates |

Announcement: name and role; disabled as unavailable. `aria-busy` on a button is announced by few screen readers, so an
app must announce the outcome of a loading action itself (a toast or a status message).
Proven by: axe sweep, `test:target-size`, `test:press`, `test:hover`, focus gate (PR #68).

### 2.2 Input and Select (field shell)

| | |
|---|---|
| Role / name | native `input` (textbox etc.) / `select` (combobox); name from the visible `<label for>` |
| Description | `aria-describedby` = app ids (PR #70), then the hint id, then the error id |
| Required | native `required`; the visual `*` is `aria-hidden` |
| Error | `aria-invalid="true"`, a 2 px (`--border-width-strong`) danger border, and a text message prefixed "Error:" |
| Disabled | native `disabled` |

| Key | Input | Select |
|---|---|---|
| Tab / Shift+Tab | into / out of the field | into / out of the field |
| Typing | edits the value | jumps to a matching option |
| Space, Enter, Alt+Down | | opens the native option list |
| Up / Down | | changes the option |

Announcement: label, role, value, "required", "invalid", then the description (app text, hint, error). The error is not a
live region: it is announced when the field is focused. On submit, the app moves focus to the first invalid field.
On main today: an app's own `aria-describedby` replaces the hint and error ids (fixed by PR #70).
Proven by: axe, `src/describedby.test.tsx` (PR #70), the mobile and text-spacing sweep.

### 2.3 Checkbox and CheckboxGroup

| | |
|---|---|
| Role / name | native `input type="checkbox"`; name from its `<label>`; the group is a `fieldset` named by its `legend` |
| States | unchecked, checked, mixed, disabled, error |
| Mixed | the native `indeterminate` property only, which browsers expose as mixed; never `aria-checked` on the input (PR #69) |
| Error | `aria-invalid="true"`, a danger outline, text "Error: ..." in the description; while focused the focus ring replaces the danger outline (PR #68) |
| Hit area | the label's `::before` covers the 44 px row |

| Key | Action |
|---|---|
| Tab / Shift+Tab | to / from each checkbox |
| Space | toggles |

On main today: `aria-checked="mixed"` is also set on the input (PR #69), and a focused checkbox in the error state shows
no focus change (PR #68).
Proven by: axe, `src/Checkbox.test.tsx` (PR #69), focus gate (PR #68), target size.

### 2.4 Switch

| | |
|---|---|
| Role / name | native `input type="checkbox"` with `role="switch"`; name from its `<label>`; hint in `aria-describedby` |
| States | off, on, disabled; on and off differ by thumb position and fill, not colour alone; forced colours use Highlight |
| Effect | applies at once (no Save needed); use Checkbox for a choice that is submitted with a form |

| Key | Action |
|---|---|
| Tab / Shift+Tab | to / from the switch |
| Space | turns it on or off |

Announcement: "switch, on/off". Proven by: unit test "is a native checkbox with role=switch, toggled by Space and by its label", axe, target size, focus gate.

### 2.5 Modal

| | |
|---|---|
| Role / name | native `<dialog>` opened with `showModal()` (role dialog, modal, page behind inert); `aria-labelledby` = the required title (`h2`) |
| Open | focus moves to the first tabbable control (the Close button) |
| Close | Esc, the Close button (`aria-label="Close dialog"`), a backdrop click, or the app setting `open={false}` or unmounting it; focus returns to the element that opened it |
| Toasts | toasts fired while open render inside the topmost modal, so they are reachable and announced (see Toast) |

| Key | Action |
|---|---|
| Tab / Shift+Tab | moves between tabbable controls inside; wraps from last to first and first to last |
| Esc | closes (only the topmost of nested modals) |
| Enter, Space | activates the focused button |

On main today: the wrap uses a selector list, so a hidden input, inactive tabs or unchecked radios can be taken as the
last control and the wrap fails (PR #67 adds `src/tabbable.ts`).
Proven by: unit tests in `src/components.test.tsx` (focus in, Esc, close-button focus return, unmount focus return,
Tab trap, nested modals), `src/Modal.test.tsx` (PR #67), `test:toast-modal`, axe with the dialog open, contrast
"dialog border / scrim" rows.

### 2.6 Tabs

| | |
|---|---|
| Roles | `tablist` (named by the required `label`), `tab` (`aria-selected`, `aria-controls`), `tabpanel` (`aria-labelledby` its tab, `tabindex="0"`, inactive panels `hidden`) |
| Activation | automatic: moving to a tab selects it |
| Roving tabindex | exactly one tab, the selected one, has `tabindex="0"`; it is always an enabled tab (PR #66) |
| Disabled tab | native `disabled`: skipped by the arrow keys and not focusable |
| Forced colours | the baseline is drawn as a border and the selected bar uses Highlight |

| Key | Action |
|---|---|
| Tab | to the selected tab, then into the panel |
| Right / Left | next / previous enabled tab, wrapping, and selects it |
| Home / End | first / last enabled tab |

On main today: a `defaultTab` that is disabled or unknown leaves no tab in the Tab order (PR #66).
Proven by: unit test "moves and selects with arrows, wraps, skips disabled, and supports Home/End",
`src/Tabs.test.tsx` (PR #66), focus gate, target size.

### 2.7 Table

| | |
|---|---|
| Structure | `<table>` with a required `<caption>`; header cells `scope="col"`; a column marked `rowHeader` renders `th scope="row"` |
| Scroll region | wrapper with `role="region"`, `aria-labelledby` the caption, `tabindex="0"` so it scrolls by keyboard (1.4.10 allows two-dimensional scrolling for data tables) |
| Sorting | sortable headers hold a `button`; the `th` has `aria-sort` `none`/`ascending`/`descending`; the arrow glyph is `aria-hidden` |
| Empty | one full-width cell with app text (default "No rows.") |

| Key | Action |
|---|---|
| Tab | to the scroll region, then each sort button |
| Enter, Space | sorts by that column; again reverses |
| Left / Right | scrolls the region when it has focus |

Announcement: the new sort is exposed through `aria-sort`, which some screen readers only read when the header is
revisited; an app that needs a confirmation adds a polite status message ("Sorted by Name, ascending").
Proven by: axe, target size (sort button), focus gate. This is a static data table, not an interactive grid.

### 2.8 Toast (ToastProvider, useToast)

| | |
|---|---|
| Regions | live regions mounted empty and kept mounted: `role="status"` (polite) for info and success, `role="alert"` (assertive) for errors |
| Content | title, optional message, optional action button, dismiss button named "Dismiss: {title}" |
| Timing | info and success dismiss after `duration` (default 5000 ms; 0 or less means never); the timer pauses on hover, on focus, while the page is inert and while the tab is hidden; errors and toasts with an action stay until dismissed (2.2.1) |
| In a modal | toasts render into an outlet inside the topmost modal dialog; each toast is announced once, also when it moves between page and modal |
| Focus | toasts never take focus; dismissing a focused toast returns focus to where it came from, or to the first control of the open dialog |

| Key | Action |
|---|---|
| Tab | reaches the action and dismiss buttons in DOM order |
| Enter, Space | runs the action (then dismisses) / dismisses |

Proven by: unit tests (roles, auto-dismiss and hover pause, sticky error and action, Undo, the six toast-in-modal tests),
`test:toast-modal` (570 checks), axe, reduced-motion check. Known open work: 2.4.11 Focus Not Obscured at narrow widths
(PR #21).

### 2.9 ThemeSwitcher

| | |
|---|---|
| Structure | two native radio groups, each a `fieldset` with a `legend` ("Theme", "Color mode"); the Theme group is hidden when one theme is registered |
| Announcement | a polite `role="status"` says "Theme {name}, {mode} mode" after each change (not on first render) |
| Persistence | `localStorage`; Auto follows the OS colour scheme live; an inline pre-paint script prevents a flash of the wrong theme |
| Motion | uses a view transition only when reduced motion is off |

| Key | Action |
|---|---|
| Tab | into each group, on the checked option |
| Arrow keys | move to and select the next / previous option in the group |
| Space | selects the focused option |

Proven by: unit tests "has two labelled radio groups and starts from storage" and "works by keyboard, persists, announces, and removes keys for the default theme and Auto", axe, target size,
focus gate (the ring is drawn on the option, the radio itself is transparent).

## 3. Test method

### 3.1 Automated

All commands run from the repository root after `npm ci`. Browser gates need a built Storybook served on port 6007:

```sh
npm run build
npx http-server storybook-static -p 6007 -s &
npx wait-on http://127.0.0.1:6007/index.json
```

| Command | Tool | What it proves | Criteria |
|---|---|---|---|
| `npm run typecheck`, `npm run lint` | TypeScript, ESLint | types (e.g. icon-only buttons need `aria-label`) | 4.1.2 |
| `npm run tokens` | own script | every theme implements the token contract and nothing else | |
| `npm run lint:colors` | own script | no raw colours or literal borders, radii, shadows or outlines in component CSS | all colour criteria |
| `npm run contrast` | own script, WCAG formula | every pair in section 1.2, every theme and mode; writes `docs/CONTRAST.md` | 1.4.3, 1.4.11 |
| `npm test` | Vitest, Testing Library, jsdom | names, roles, keyboard, focus movement, live regions, timing | 2.1.1, 2.1.2, 2.2.1, 2.4.3, 4.1.2, 4.1.3 |
| `npm run test:a11y` | axe-core in Chrome via Playwright | every story and docs page, every theme and mode, OS dark; serious or critical fails; no animation under reduced motion | many, 2.3.3 |
| `npm run test:mobile` | Playwright + axe | docs pages at 320 to 1440 px (640 = 200 % zoom of 1280): no page overflow, 44 px targets, text-spacing overrides | 1.4.4, 1.4.10, 1.4.12, 2.5.8 |
| `npm run test:target-size` | Chrome hit-testing | effective hit area of every control, 320 and 1280 px; `--calibrate` and `--negative-control` prove the gate | 2.5.8 |
| `npm run test:focus-visible` | Playwright screenshots (PR #68) | every focus stop changes pixels; outlines 2 px or more; light, dark, forced colours; `--negative-control` | 2.4.7 |
| `npm run test:toast-modal` | Playwright + axe | toasts inside modals: reachable, announced once, timers, every theme, mode and width | 2.1.1, 2.2.1, 4.1.3 |
| `npm run test:press`, `npm run test:hover` | Playwright | press offset (0 under reduced motion), hover colours, forced colours | 2.3.3, 1.4.11 |
| `node scripts/focus-obscured.mjs` | Playwright | focus stops hidden by the toast stack | 2.4.11 |

Each browser gate that can pass vacuously has a negative control: a planted defect it must catch.

|---|---|---|
| Screen reader announcements | NVDA + Firefox or Chrome on Windows, VoiceOver + Safari on macOS and iOS, TalkBack + Chrome on Android: walk every story; record what is said for name, role, state changes, errors and toasts | not yet recorded (the ACR marks 4.1.3 and 302.1 partial for this reason) |
| Keyboard pass in a real app | Tab through a page that uses every component; confirm order, no traps, visible focus | covered by gates per component; an app page is the app's job |
| Text-only zoom | browser setting "font size: very large" (200 %); nothing clipped or overlapping | not automated |
| Forced colours on Windows | High Contrast themes (dark and light): every state still visible | partly automated (Chrome emulation), not on Windows |
| Wording | error messages say how to fix; toast titles make sense alone | app-owned |

## 4. Patterns to copy and anti-patterns

| Do | Don't | Why |
|---|---|---|
| Use the native element (`button`, `dialog` with `showModal()`, `select`, checkbox with `role="switch"`) | Build controls from `div` and `span` with click handlers | Native elements bring focus, keys, roles and form behaviour for free |
| Draw focus with one shared `:focus-visible` outline from tokens, 2 px or more, 3:1 on every surface | Remove the outline, or draw focus only with a shadow or colour shift | Shadows vanish in forced colours; a colour shift alone may not reach 3:1 |
| When a state also uses `outline` (error, selected), add a more specific `:focus-visible` rule for that state | Let a later state rule with equal specificity set `outline` | It silently replaces the focus ring (found here in Checkbox error) |
| Keep a hit area of 44 px with a `::before` overlay or a row-wide label while the visual stays small | Grow every control visually, or leave 20 px checkboxes as the only target | Meets 2.5.5/2.5.8 without changing the design |
| Let the native `indeterminate` property carry the mixed state | Put `aria-checked` on `<input type="checkbox">` | ARIA in HTML forbids it, and it goes stale after a click |
| Merge an app's `aria-describedby` with your hint and error ids | Spread the app's props over your own `aria-describedby` | The hint and the error stop being announced |
| Compute a focus trap from tabbable elements (tabindex 0 or more, enabled, rendered, not `type="hidden"`, one radio per group) | Use a "focusable" selector list | Hidden inputs, inactive tabs and closed panels break the wrap |
| Keep exactly one enabled item in the Tab order of a roving-tabindex widget, whatever props say | Trust `defaultTab`/`defaultValue` without checking it is enabled and present | The whole widget can drop out of the Tab order |
| Mount live regions empty and keep them mounted; add messages later | Mount a region together with its message | Screen readers announce changes, not initial content |
| Render toasts inside an open modal dialog | Show them in the page while a modal makes the page inert | They are neither announced nor reachable |
| Keep toasts with an action, and errors, until dismissed; pause timers on hover, focus, inert and hidden tab | Auto-dismiss something the user must read or act on | 2.2.1 Timing Adjustable |
| Show errors as text ("Error: ..."), `aria-invalid` and a thicker border | Mark errors by red colour only | 1.4.1 Use of Color, 3.3.1 |
| Zero motion in the tokens under `prefers-reduced-motion` | Add per-component media queries one by one | One place to audit; new components inherit it |
| Use forced-colours rules with system colours (`CanvasText`, `Highlight`) where a state was drawn with backgrounds or shadows | Rely on background images or box shadows for state | Forced colours drop them |
| Composite translucent colours before measuring contrast | Measure a scrim's colour as if opaque | The ratio is wrong in both directions |
| Gate each check with a negative control | Trust a gate that has never failed | A gate can pass because it measures nothing |
| In Storybook with the pseudo-states addon, write positive state selectors (`:focus-visible`) | Use `:not(:focus-visible)` | The addon rewrites `:not(...)` into a selector list that still matches, so stories lie |

## 5. What Ember UI does not cover

The app owns these; nothing in Ember checks them:

- Page structure: `lang`, `title`, one `h1` and heading order, landmarks, skip link (2.4.1, 2.4.2, 3.1.1, 1.3.1).
- Focus management between views and after route changes; announcing page changes in a single-page app.
- Form-level validation: error summaries, moving focus to the first invalid field on submit, server-side errors, the
  wording of messages (3.3.1, 3.3.3, 3.3.4).
- Announcing the outcome of loading buttons and of table sorting, when the app wants a spoken confirmation.
- Widgets Ember doesn't ship: combobox and autocomplete, menus and menu buttons, tooltips, disclosure and accordion,
  date pickers, sliders, tree views, interactive data grids, drag and drop, carousels, pagination, breadcrumbs, links.
- Media: the VideoPlayer (`ember-ui/video`) is a separate entry still in progress; captions, audio description and
  transcripts are not covered by this file.
- Right-to-left layouts: Ember uses physical properties (`left`, `margin-left`), so RTL is untested.
- `prefers-contrast: more` (no high-contrast token set) and 7:1 (AAA) contrast.
- Session and authentication timing, CAPTCHAs, accessible authentication (2.2.1, 3.3.8).
- Images and their text alternatives, charts and data visualisation.
- A recorded screen-reader pass (section 3.2) and a third-party audit; the ACR is self-assessed.
