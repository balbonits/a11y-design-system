UX case study 01

Ember UI: an accessible design system starter

I built a small design system from the ground up: tokens first, eight core components, and documentation that explains how each one works by keyboard and for screen readers.

Problem

Accessibility arrives late

Most teams bolt it on at the end.

Approach

Tokens first

Every component built and documented against WCAG 2.2 AA.

Prototype for review. Motion respects your reduced-motion setting. Marquee pauses on hover, focus, or the Pause button.
